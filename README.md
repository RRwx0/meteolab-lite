# MeteoLab Lite + WtS

Облакоразрешающая модель глубокой конвекции в браузере плюс серверная массовая
загрузка аэрологических зондирований Wyoming в формат SHARPpy.

- Готовый сайт одним файлом: `meteolab-lite.html`
- Исходники сайта: `src/index.html`, `src/styles.css`, восемь модулей в `src/*.js`
- Серверная часть WtS: пакет `wts/` (Python 3.9+, только стандартная библиотека)
- Тесты: `tests/test_wts.py` (сеть замокана, реальный ответ лежит в `tests/fixtures`)

## Запуск

### 1. Сайт без сервера (как раньше)

Двойной щелчок по `meteolab-lite.html` — модель, радар, торнадо и сигнатуры
работают офлайн. Раздел «Зонды WtS ⧉» откроется, но серверная загрузка в этом
режиме недоступна: браузер не может сам запускать Python.

### 2. Сайт с массовой загрузкой — без команд

Двойной щелчок по **`WtS.cmd`**. Скрипт сам:

- проверяет, не запущен ли сервер;
- поднимает `python -m wts` в скрытом окне, если его нет;
- ждёт ответа API и открывает `http://127.0.0.1:8770/`;
- при повторном запуске просто открывает сайт.

Дополнительные ярлыки:

| Файл | Что делает |
| --- | --- |
| `WtS.cmd` | запустить сервер и открыть сайт |
| `WtS-stop.cmd` | остановить сервер |
| `WtS-autostart.cmd` | включить/выключить автозапуск при входе в Windows (первый щелчок — включить, второй — выключить) |

Автозапуск создаёт ярлык `MeteoLab WtS.lnk` в папке «Автозагрузка» и поднимает
сервер в фоне при входе в систему — тогда сайт из `meteolab-lite.html` сразу
находит API, и никаких действий вообще не требуется. Отключается тем же
`WtS-autostart.cmd`.

Если Python не найден или порт занят чужой программой, лаунчер покажет окно с
выводом Python. Порт и каталог результатов можно изменить в `wts-service.ps1`
(параметр `-Port`) или переменными окружения из `.env.example`.

### 3. Ручной запуск (как раньше)

```text
cd <папка проекта>
python -m wts --open
```

Откроется `http://127.0.0.1:8770/` — тот же сайт, но с работающим API.
Кнопка **«Зонды WtS ⧉»** в верхней панели открывает раздел загрузки.

Параметры (или переменные окружения из `.env.example`):

```text
python -m wts --host 127.0.0.1 --port 8770 --data-dir "%USERPROFILE%\.meteolab\wts" --ttl-hours 24 --max-jobs 8
```

Повторный запуск на занятом порту не падает: если API уже отвечает, сервер
сообщает «WtS уже запущен» и открывает сайт.

Внешние пакеты не нужны: `pip install -r requirements.txt` ничего не ставит.
Установка Python: 3.9 и новее (проверялось на 3.13).

Хостинг: обычный статический хостинг Python не выполняет. Нужен любой сервер с
Python; приложение слушает только loopback и не имеет авторизации, поэтому
наружу его выставлять не следует.

## Раздел «Зонды WtS»

Перенесены все возможности исходной `WtS_mass.py`, кроме Tkinter:

- станция из списка 19 пунктов и ручной WMO ID (список синхронизируется);
- начальная и конечная дата, быстрые кнопки «Последний месяц» и «Последний год»;
- сроки 00 и 12 UTC;
- число параллельных запросов (1–10) и задержка между запросами (0–30 с);
- СТАРТ и СТОП, прогресс, счётчики «всего / прогресс / успешно / ошибки / пропущено»;
- журнал: время, дата, срок, статус, сообщение об ошибке;
- вкладка «Файлы»: симуляция по зондажу кнопкой «В модель», скачивание каждого `.snd` и архива ZIP;
- раскладка результатов `год / "MM - Месяц" / "HH UTC"` (можно отключить).

Данные берутся с того же сервера Wyoming, что и в исходной программе:

```text
https://weather.arcc.uwyo.edu/wsgi/sounding?datetime=YYYY-MM-DD HH:00:00&id=<WMO>&src=UNKNOWN&type=TEXT:LIST
```

### Единицы измерения

Проверено на реальном ответе (24959, 2024-06-01 12 UTC): сервер отдаёт колонку
`SPED` со строкой единиц `m/s`. Формат SHARPpy ожидает узлы, поэтому скорость
умножается на 1,943844 **только** после того, как единица подтверждена строкой
единиц или именем колонки. Если в ответе `SKNT`/`kt`, коэффициент не применяется.
Высота — метры, давление — гПа, температура и точка росы — °C, направление — градусы.

### Формат .snd

```text
%TITLE%
 24959   240601/1200
   LEVEL      HGHT       TEMP       DWPT       WDIR       WSPD
------------------------------------------------------------------
%RAW%
 1000.0,     101.0,      20.2,      15.2,       0.0,       0.0
 ...
%END%
```

Числа округлены до 0,1; порядок колонок — давление, высота, температура, точка
росы, направление, скорость в узлах.

### Зондаж → симуляция

Кнопка **«В модель»** у файла во вкладке «Файлы»:

1. скачивает `.snd` с сервера WtS;
2. разбирает `%TITLE%`/`%RAW%`, переводит узлы в м/с и достаёт станцию и срок;
3. строит профиль (`ML.sounding.fromObserved`): CAPE, CIN, LCL, сдвиг, SRH;
4. подставляет его в модель вместо параметрического профиля, сбрасывает поле
   и запускает расчёт — дальше работают радар, мезоциклоны, торнадо и сигнатуры.

Всё это происходит в самой программе симуляции: сервер отдаёт только файл,
расчёт идёт в браузере. Применённый зондаж попадает в список «Реальное
зондирование» и сохраняется в браузере, поэтому его можно выбрать повторно.

Формат `.snd` понимает и обычная панель импорта: вставьте текст файла, укажите
его в поле «Файл» (`.snd` разрешён) или пришлите ссылку. Для формата SHARPpy
единицы ветра — узлы, в модель они пересчитываются в м/с (×0,514444).

## API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/wts/health` | состояние сервера, версия, число активных задач |
| `GET /api/wts/stations` | список станций и допустимых сроков |
| `POST /api/wts/jobs` | создать задачу: `{station, start, end, hours, workers, delay, organize}` |
| `GET /api/wts/jobs/{id}?since=N` | статус, счётчики, журнал после записи N |
| `POST /api/wts/jobs/{id}/stop` | остановка |
| `GET /api/wts/jobs/{id}/files` | список `.snd` со ссылками и ZIP |
| `GET /api/wts/jobs/{id}/file?path=…` | скачать один файл (только внутри задачи) |
| `GET /api/wts/jobs/{id}/zip` | архив результатов |
| `DELETE /api/wts/jobs/{id}` | удалить задачу и её файлы |

Даты принимаются как `YYYY-MM-DD`, `{y,m,d}` или `[y,m,d]`; сроки — `["00","12"]`.
Ошибки валидации — 400 с текстом, неизвестная задача — 404, путь вне каталога
задачи — 400. Прогресс обновляется опросом раз в 0,7 с (без SSE и WebSocket).

## Устройство серверной части

- `wts/wyoming.py` — URL, HTTP-запрос, разбор ответа (в том числе неполных строк),
  определение единиц ветра; 404 и маркеры «No data» → пропуск, а не ошибка.
- `wts/snd.py` — запись `.snd` и независимый мини-парсер для самопроверки.
- `wts/planner.py` — станции, даты, сроки, быстрые диапазоны, лимиты (5000 зондов).
- `wts/jobs.py` — фоновые задачи: пул потоков, задержка, остановка, счётчики,
  журнал, каталог на задачу, ZIP, очистка по TTL, защита путей.
- `wts/server.py` — `ThreadingHTTPServer`: API и отдача сайта; результаты лежат
  вне публичного каталога и доступны только по id задачи.
- `wts/__main__.py` — `python -m wts`.

## Проверка

```text
python -m unittest discover -s tests -v
multitool-node test-core.js
multitool-node --skill websites site.cjs check meteolab-lite.html
multitool-node --skill websites verify.cjs meteolab-lite.html --actions actions.json
```

Сценарии браузерной проверки: `actions.json` (основной интерфейс),
`actions-obs.json` (импорт зондирования), `actions-obs-snd.json` (файл SHARPpy
`.snd` → профиль → симуляция), `actions-radar.json` (радар),
`actions-scenario.json` (гроза + мезоциклон), `actions-wts.json` (раздел WtS).

Ручная проверка одного реального запроса:

```text
python -m wts --port 8791
python check-e2e.py
```

## Что проверено, а что нет

Выполнено:

- 40 тестов Python: разбор реального ответа Wyoming, единицы, `.snd`, планирование,
  задачи, API, обход путей, 404 и сетевые сбои на моках;
- полный цикл на живом сервере: задача 24959 / 2024-06-01 12 UTC → файл
  3825 байт → ZIP 1472 байта (один реальный запрос к Wyoming);
- сборка бандла, `site.cjs check` без ошибок, `verify.cjs` — OK для всех шести
  наборов действий на 1440 и 390 px;
- разбор `.snd` в браузере: реальный файл 24959 / 2024-06-01 12 UTC даёт 58 уровней,
  CAPE 2417 Дж/кг, сдвиг 0–6 км 14 м/с; профиль применяется к модели (сценарий
  `actions-obs-snd.json` с проверкой значений на экране);
- ядро модели: `test-core.js` на 48² и 40², сетка 120×120×16 — 61 мс на шаг.

Не проверено:

- SHARPpy не устанавливался и не открывал файлы: совместимость подтверждена
  структурой формата и независимым парсером, а не запуском SHARPpy;
- совместная работа браузерного раздела и живого API не проверена автоматически:
  встроенный `verify.cjs` блокирует сеть, поэтому UI проверен офлайн, а API —
  отдельными HTTP-запросами. Кнопка «В модель» проверена на файле из фикстуры,
  но не в связке с живым сервером; требуется ручное открытие `http://127.0.0.1:8770/`;
- массовые реальные загрузки не выполнялись (щадящий режим к серверу Wyoming).

## Модель (как было)

- **11 типов гроз**, профиль, сдвиг и геометрия запуска: импульсная, мультиячейка,
  суперячейка, LP/HP, шквальная линия, кластер МКС, градовая, сухая, тропическая,
  поле кучевых.
- **Сетка 120×120×24** по умолчанию (Δx = 1 км, Δz = 500 м, Δt = 4 с) и 40²/48²/56²
  для слабых машин; один шаг за кадр на больших сетках.
- **Диагностика**: CAPE, CIN, DCAPE, PWAT, LCL, LFC, EL, сдвиг 0–6 и 0–1 км,
  SRH 0–3, BRN, UH 2–5 км, мезоциклоны.
- **Сигнатуры полей**: осадки, лёд, завихрённость ζ, θ′, w, q_v, UH, холодный купол.
- **Окно торнадо** открывается только при выполнении всех условий (мезоциклон,
  STP ≥ 1, SRH 0–1 ≥ 100, LCL ≤ 1200 м, сдвиг 0–1 ≥ 6 м/с, Vrot ≥ 6 м/с,
  холодный купол не холоднее −3 K); иначе показывается чек-лист причин.
- **Ограничения**: полулагранжева адвекция, приближение Буссинеска, нет радиации,
  рельефа и двухмоментной микрофизики. Числа — результат упрощённой модели.
